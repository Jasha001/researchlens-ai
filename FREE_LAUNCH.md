# ResearchLens 5.2 — Render Free + Neon Free

This package adapts the current app for ongoing free-tier hosting, not an expiring hosting trial. No public service/account/purchase has been created. Free-tier terms and availability can change; this is not an uptime guarantee.

## Configuration prepared
- Render Docker web service: render.yaml explicitly selects plan: free. No Render database or persistent disk is provisioned.
- Neon Postgres holds quota counters/short concurrency leases. If it is unavailable, protected operations fail closed; they do not switch to local counters.
- Free-host mode: 5 MB upload, 20 pages, text-based PDFs only, one parser process and one provider request at a time. OCR remains available in ordinary local mode. The parser has a 256 MiB address-space cap in free mode (actual host memory still needs measurement).
- 60 Gemini provider calls/day globally, 10/session/day in render.yaml. Most answers use two calls; expect roughly 30 complete answers/day. Failed calls count. Global budgets survive Render restarts through Neon. Anonymous sessions are not per-person identities.
- Public invited-code gate, session-bound documents, CSRF, exact-origin checks, TLS database connection with server identity verification, server-only secrets, no automatically enabled paid API or hosting.
- One known LIME failure case now rejects claims that drop the cited local-nonlinearity condition. This narrow check does not prove general factual accuracy.

## Accounts needed (free plans only)
1. GitHub: put the source in a NEW dedicated repository; exclude .env, .env.public, runtime, node_modules and all credentials. Public or private repository is a choice for the owner; never upload keys even to a private repo.
2. Neon: create a separate project on the FREE plan. Select an appropriate region near the Render region. Copy the pooled PostgreSQL connection string into Render's DATABASE_URL secret; keep its TLS parameters. Do not paste the connection string into chat or commit it.
3. Render: New Blueprint, select that GitHub repo, confirm the service plan says FREE. Do not add a Render Postgres service: its free database expires. render.yaml creates only one web service.
4. In the Render secret prompts set GEMINI_API_KEY, DATABASE_URL, SITE_ACCESS_CODE (a private random 16+ character code) and PRIVACY_CONTACT (email to show publicly). SESSION_SECRET is generated by the Blueprint; keep it stable across deploys. Do not use the Gemini key as the access code.
5. Leave APP_ORIGIN unset initially. PUBLIC_MODE uses Render's RENDER_EXTERNAL_HOSTNAME to derive the exact HTTPS origin. For a custom domain later set APP_ORIGIN to that domain; certificate and cookie/Origin checks must be retested.
6. Deploy and open the actual https://...onrender.com URL directly, not an embedded preview. Test wrong/valid code, upload, English/Bengali answers and unsupported questions.

## Required deployment checks — not completed here
- Verify Neon connectivity/TLS and quota persistence using `python scripts/check_database.py` in an environment with the private DATABASE_URL. It makes no AI calls and only removes its own test rows. The helper reads root .env if run locally; do not share that file.
- Verify real Render build/health checks, cold start, 512MB memory behavior, simultaneous clients, process restart and real Gemini errors. Application-memory constraints cannot guarantee the platform never runs out of memory.
- Use two browsers to verify each cannot submit the other's paper token. Inspect Secure/HttpOnly cookies and missing/wrong CSRF rejection. Ensure .env/.env.public/source/quota DB are not publicly served.
- Keep the API project's billing disabled for free-only operation and do not authorize hosting upgrades. Free quotas stop/limit service, not guarantee unlimited access. Do not configure fake keep-alive traffic to defeat host sleeping policies.
- Public privacy/contact notice must match your actual host settings. Host access logs and Neon provider logs are outside this app's own retention behavior. Only use public papers, never patient/confidential records.

## Operational limits
Render Free sleeps after 15 minutes of inactivity and can take about a minute to wake up. Free CPU/memory, bandwidth/build allowances, outbound-traffic restrictions and restarts affect availability. Neon compute can sleep and is quota-limited too. A public hobby/research beta can use these plans; Render advises against relying on free services for production. If always-on reliable hosting is required, this free architecture does not provide it.

The app deliberately ignores X-Forwarded-For. Visitors behind Render's proxy may share IP-derived throttles; this conservatively reduces capacity. Do not enable untrusted proxy headers just to avoid throttling. SQLite remains the local default, so your current Mac setup does not need Neon.

ESP retrieval experiments and the independent XAI research paper remain separate; no experimental result or admission benefit is claimed.
